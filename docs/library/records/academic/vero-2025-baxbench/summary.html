Overview

BaxBench asks whether language models can write a whole, deployable application module, choosing web backends because they are common, take several functions and files, and face untrusted users (§1). It combines 28 scenarios specified in OpenAPI with 14 frameworks in six languages into 392 tasks, and checks each generated backend with functional tests and with expert-written end-to-end exploits, rather than static analysis, against 13 CWEs (§2, §3, Table 5). Across 11 models the best correctness is 62% (OpenAI o1) and the best rate of correct and secure code is 37% (OpenAI o3-mini); the exploits succeed against about half of the correct programs, and models do worse in less popular frameworks such as Rust-Actix and PHP-Lumen (§1, §4, Figures 1, 3 and 5). A generic security reminder helps reasoning models but not others, a reminder that names every expected vulnerability raises security at some cost to correctness, and a coding agent improves security only with that reminder (§4, Table 2).

Limits

  • Security is an upper bound. A program counts as secure when none of the exploits succeeds, so the score depends on the exploit set. Compared with Snyk Code on o1's 237 correct programs, the exploits caught 64 vulnerable programs Snyk missed, while Snyk raised 7 valid flags the exploits did not confirm (§4).
  • Mostly single-shot generation. Ten samples per task for non-reasoning models and one for reasoning models; the only agent experiment is OpenHands with Claude 3.5 Sonnet on 351 tasks (§4).
  • Small applications. About two endpoints per scenario; the authors present the tasks as simpler real-world backends (§3, §5).
  • Contamination is possible once the benchmark is public, though golden solutions are withheld (§5).
  • The numbers changed between versions. v1 reported o1 at 60% correct, more than half of correct programs exploitable and a best correct-and-secure rate of 35%; v3 reports 62%, about half and 37%. v3's Figure 3 caption still says 35%.
  • Early-2025 models, since superseded.
