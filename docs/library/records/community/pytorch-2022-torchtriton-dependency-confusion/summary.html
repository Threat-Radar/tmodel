Overview

PyTorch tells users who installed PyTorch-nightly on Linux with pip between 25 and 30 December 2022 to uninstall it and torchtriton at once. Someone had uploaded a package named torchtriton to PyPI, the same name as a dependency PyTorch ships on its own nightly index. Because pip gives PyPI precedence over the extra index, it installed the attacker's package instead: the post calls this a supply chain attack on dependencies hosted on public indices. The package carried a malicious triton binary, whose SHA-256 the post gives. When run, it collected system information (nameservers, hostname, user name, working directory, environment variables) and read /etc/hosts, /etc/passwd, $HOME/.gitconfig, the files in $HOME/.ssh and the first 1,000 files in $HOME. It uploaded all of it, files only if under 99,999 bytes, through encrypted DNS queries to a domain under h4ck[.]cfd. The binary ran only when code imported triton, which PyTorch does not do by default, and stable releases were not affected. The post gives a one-line check for the binary. It lists the response: the dependency renamed to pytorch-triton (pytorch/pytorch#91539), a placeholder torchtriton registered on PyPI, the affected nightlies removed from download.pytorch.org, and a request to PyPI's security team for ownership of the name and deletion of the malicious version.

Limits

  • Written the day after discovery. It gives no count of affected installs, no attribution and no timeline of the package's upload.
  • Narrower than "installed". By the post's own account the binary ran only if code imported triton; how often that happened is not stated.
  • Only the pip route on Linux is described; other installation routes are not discussed.
