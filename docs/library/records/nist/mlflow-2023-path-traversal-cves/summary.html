Overview

Both records say only "Path Traversal: '\..\filename' in GitHub repository mlflow/mlflow", before 2.2.1 and before 2.9.2. The substance is elsewhere. CVE-2023-1177 is the serious one. Its huntr report, filed on 3 March 2023 for the CVE after private disclosure to the maintainers, shows that a default mlflow server or mlflow ui, with no authentication, lets anyone register a model, create a model version whose source is a local directory (the example is the server user's .ssh folder), and then download any file in it through the model-version artifact endpoint. A source such as an S3 bucket extends this to the remote artifact store. The report argues that most deployments use S3, so cloud credentials can be stolen, and that stolen SSH keys allow takeover. The maintainers' advisory (GHSA-xg73-94fp-g449) confirms that an actor can download arbitrary files from the host and from remote locations the server can reach. It limits the impact to mlflow server and mlflow ui (not Databricks Managed MLflow or MLflow on Azure Machine Learning), and recommends restricting who can reach the server and scoping its cloud credentials to MLflow files. huntr scores it CVSS 3.1 9.3 with CWE-29; NVD scores it 9.8 with CWE-22; CISA's enrichment records proof-of-concept exploitation, automatable, partial technical impact. CVE-2023-6831, fixed in December 2023, is a later bypass: MLflow's path check validated a URL before decoding it, so an encoded path got through (PR #10650). It needs low privileges and is scored 8.1, for integrity and availability rather than confidentiality.

Limits

  • The CVE text says almost nothing. The detail comes from the huntr report, read from the Internet Archive's copy of 2023-03-27 because huntr.com was down for maintenance on 2026-11-02, and from the maintainers' advisory in GitHub's advisory database.
  • The linked patch is not the one the release notes name. CVE-2023-1177's record and the huntr report link commit 7162a50c, from PR #7891, which applies path validation to the /mlflow-artifacts/ endpoints. MLflow 2.2.1's release notes name PR #7908, which blocks local model-version sources, the route the report uses.
  • Impact beyond the file read is the reporter's claim. That most deployments use S3 rests on a Shodan survey the report does not present, and takeover through SSH keys is argued, not shown.
  • No report text for CVE-2023-6831. The archived huntr page holds no report content; the description here comes from the fix and the CVSS vector.
  • The scores differ. huntr 9.3 against NVD 9.8, and CWE-29 against CWE-22; RPT-0014 quotes huntr's 9.3.
