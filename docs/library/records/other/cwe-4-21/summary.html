Overview

CWE 4.21 is MITRE's October 2026 catalog of software and hardware weakness types, in the same XML format as 4.20 (schema 7.x). MITRE released it beside CWE 5.0, which moves to schema 8.0 (namespace http://cwe.mitre.org/cwe-8, Categories become Groupings). The two carry the same 984 weaknesses, with identical IDs and names, so 4.21 is the newest list a schema 7.x reader can take. It is not a clean 7.x file: it carries some of 5.0's new content in places schema 7.4 does not allow (see below).

Schema 7.4, and where 4.21 departs from it

Schema 7.4 declares the same elements and attributes as 7.3, less one: Demonstrative_Example no longer has a References child. It also makes the three children of Content_History/Modification required and rewords some documentation.

The 4.21 file does not validate against schema 7.4. Checked with xmllint (libxml2 2.13.9) offline, using the W3C catalog recipe in ../cwe/distilled/schema/README.md; the 4.20 file still validates against 7.3 the same way. Every one of the 81 errors is content schema 8.0 adds:

Applicability

  • Security: core. The same vocabulary as cwe; CVE records and NVD cite CWE IDs.
  • Cryptography: adjacent. Covers cryptographic weaknesses as entries; not a cryptographic specification.
  • This project: core. The CWE release tmodel's engine serves and its app ships, pinned by this record's digest (DEC-008; tmodel ADR-0014, a cached pinned mirror). It keys tmodel's Weakness type (ARCH-0001 §3, R-010). Its departures bear on DEC-002 (import formats): a reader that rejects files failing their declared schema would reject this release.

Limits

  • Summary bar, not FX-1: the full extraction stays with cwe (4.20, schema 7.3). Extracting the CWE line again, for schema 8.0 and CWE 5.0, belongs to tmodel #61.
  • The record pins the XML distribution only. CSV and HTML views, and MITRE's web pages, were not examined.
  • 4.21 and 5.0 were compared on weakness IDs and names only. Categories (Groupings in 5.0), views and relationships were not compared.
  • Deprecated entries stay in the file, so links made before 4.21 can point at a retired entry. The owasp-asvs-5 record links 8 requirements to CWE-613, as inferred legacy mappings (OWASP dropped CWE mappings in ASVS 5.0). Those links are left as they are; whether to remap them is that record's call.
