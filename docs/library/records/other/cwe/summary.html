Overview

CWE is a catalog of software and hardware weakness types, published by MITRE as one XML file per release and validated by a closed XML Schema. Each entry has a permanent integer id (CWE-79) that is never reused, even after deprecation. Entries are Weaknesses (at Pillar, Class, Base, Variant or Compound abstraction; Simple, Chain or Composite structure), Categories and Views. Relations between weaknesses are typed and scoped to a view (ChildOf in view 1000 can differ from ChildOf in view 1003). Every entry also says whether it may be used to map real vulnerabilities (Mapping_Notes/Usage).

Applicability

  • Security: core. The common vocabulary for weakness classes; CVE records and NVD cite it.
  • Cryptography: adjacent. Covers cryptographic weaknesses as entries; not a cryptographic specification.
  • This project: core. The external key for tmodel's Weakness type (ARCH-0001 §3, R-010); its typed, view-scoped relations test the edge model accepted as DEC-001a (ADR-0010); its file-per-release distribution bears on DEC-008 (mirror vs live lookup, open) and its closed XSD on DEC-002 (import formats, accepted as ADR-0007). Details in distilled/design-notes.md.

Limits

  • The record pins the XML distribution only. CSV and HTML views, and any MITRE web API, were not examined.
  • The schema's documentation contradicts its own structure in places (source_defects in distilled/requirements.yaml), and the 4.20 data departs from the documentation in a few more (invariants I15, I16 and I29 in distilled/examples/catalog-stats.yaml; see also distilled/verification.md). The XSD is treated as authoritative for structure.
  • MITRE's root-cause mapping guidance (which prefers Base and Variant entries) is a separate document and not covered here.
